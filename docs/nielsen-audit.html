01

系统状态可见性

Visibility of system status · 4.0 / 5

做到

存储写满有不可忽略的警报。StorageQuotaBanner 用 role="alert" aria-live="assertive"，刻意不自动消失，并且关闭后再次写失败会重新弹出——注释里明说「关闭不等于永久静音」。这是全项目对状态可见性最认真的一处。

做到

AI 的「示例模式」在界面上标了出来。沉浸聊天有 focus.imm.chat.demoBadge、时间轴有 history.aiDemoNote、角色页有 gm.localNote、场景助手有 scenario.ai.noKey、设置语气包有 settings.tone.exampleNote——五处入口都提示了「这是离线示例，不是真 AI」。

做到

加载态不闪。AppRoutes 在首屏渲染后用 requestIdleCallback 预取全部路由 chunk，让大多数导航根本触发不到 Suspense，避免骨架屏「闪一下」。设置页还直接显示 localStorage 占用（settings.data.usage）。

缺口

AI 运行时失败会静默降级成示例回复。src/utils/ai/aiChat.js:68 与 :79 两处 catch { return sampleReply(); } 不带任何标记。配了 key 的用户断网时会拿到一条示例回复，却以为伙伴真的这么回答了——这比报错更糟，因为它污染的是用户对 AI 是否可信的判断。

对照组：Memo/AiTaskModal.jsx 做对了，把 error / refineFailed / refineNone 分成三种文案显示。

观察

没有任何「已保存」指示。所有数据静默写入 localStorage。对多数用户这没问题（无保存按钮即无保存焦虑），但用户没有任何依据判断「刚才那条随记进去了没有」，尤其在配额已满、写入实际失败但还没触发警报的窗口期。

建议给 sampleReply() 的返回值打上 degraded: true，聊天气泡上复用已有的 demoBadge 样式显示「AI 未连上 · 这是示例回复」。改动局限在 aiChat.js 与两个聊天组件。
02

贴近用户的真实世界

Match between system and the real world · 4.5 / 5

做到

信息架构照着真实工作流排，不是照着数据模型排。Tutorial/index.jsx 的六个阶段——捕捉 → 理清 → 专注 → 复盘 → 成长 → 定制——就是用户脑子里的顺序，每个阶段挂真实入口而不是术语解释。

做到

侧栏分区名说的是用途不是模块。「每日 / 奖励 / 回顾 / 配置」，加上主页单独领头（注释：「它是回到一切的入口，别埋在每日列表中间」）。回顾三页还写死了各管一件事的边界：时间轴＝何时发生、数据分析＝统计图表、分心统计＝只管分心。

做到

语言不评判。空态文案是「没有临近的截止日，路上很空旷 🌿」「去开始一次专注吧！」，而不是「0 条记录」或「你还没有完成任何任务」。这对 ADHD 目标人群是设计决策，不是修辞。

观察

自创隐喻有学习成本。「功能树」「场景」「标本瓶架」「生态缸」「委托」这些词在第一次见到时无法从字面推断作用。这是游戏化的必要代价，但意味着首启引导比一般工具软件更重要——见 原则 10。

03

用户控制与自由

User control and freedom · 4.5 / 5

做到

删除可撤销，并且恢复回原位置。useUndoDelete.js 记住 index，撤销时 RESTORE 把条目插回原下标而不是追加到末尾；onDelete 返回的 meta 让副作用也能一并回滚。Toast 带 aria-live="polite"，并保留内容到离场动画结束。

做到

功能开关全程可逆且不删数据。FeatureContext 用两份方向相反的名单（功能树默认全开、废弃页面默认全关），关掉组时子项自己的记忆不动，重开即恢复原样。核心页永远不可关。这是「用户随时能反悔」原则少见的彻底实现。

做到

老链接不会走死。/flow-tasks → /tasks、/history → /calendar、以及 * 兜底全部 Navigate replace，被关掉的功能直接弹回主页而不是白屏。数据可整体导出/导入。

缺口

撤销只覆盖两条数据线。useUndoDelete 只接进了 TodoContext 与 ScenarioContext。随记删除（Memo/MemoItem.jsx）与 DDL 检查点删除（DDLReminders/index.jsx:113）——后者是一次点击直接销毁，既无确认也无撤销。同一个动作在不同页面后果不同，这同时也是 原则 4 的问题。

观察

5 秒撤销窗口对目标人群偏短。UNDO_WINDOW_MS = 5000。注意力容易被打断的用户，很可能在 toast 消失后才反应过来点错了。10 秒是更贴合人群的默认值，成本是一行常量。

建议把 useUndoDelete 接到随记与 DDL 检查点上（hook 已经是通用形状，接入成本低），并把窗口调到 10 秒。
04

一致性与标准

Consistency and standards · 4.0 / 5

做到

一致性有自动化守护，不靠人眼。i18n/i18n.test.js 用 import.meta.glob 抓全部命名空间，钉死四条约定：每条词条中英都在、没有拼错的语言字段、同一 key 不在两个文件里重复定义、中英占位符集合一致。1000+ 词条靠人守不住，这是正确的工程判断。

做到

导航是单一数据源。navSections.js 同时喂侧栏、全局搜索的页面结果、沉浸浮层导航和分心记录的页面名还原（PAGE_LABEL_KEYS）。注释直说：「两处各写一份的话，加个页面必然漏掉一边。」

做到

视觉与 AI 调用都收在一处。styles/theme.css 把所有透明衍生色从 --accent-rgb 派生，换主色只改一行；六个 AI 模块共用 aiClient.js 的三模式底座，形状统一。

缺口

确认交互有两套并存。一套是 useConfirm + ConfirmDialog（焦点陷阱、Esc 关闭、danger 样式），用在 6 处；另一套是 Settings/DataSection.jsx 里的内联「确认清空 / 取消」按钮对。清空数据是全站最危险的操作，反而用了较弱的那套。

结果是同一类破坏性动作在三种形态之间跳：模态确认、内联确认、以及上一条提到的什么都没有。

建议把 DataSection 的两处清空改用 useConfirm({ danger: true })，让「破坏性操作 ⇒ 模态确认」成为无例外的规则。
05

防错

Error prevention · 3.5 / 5

做到

危险选项默认关闭且要显式打开。导入数据的「替换现有数据」是独立勾选（settings.data.importReplace），不勾就是合并。核心功能在 FeatureContext 里硬编码为不可关，路由层再由 FeatureGate 兜一次——用户不可能把自己锁在门外。

做到

对模型输出的防御是真的。extractJson 剥代码围栏、定位首尾括号、解析失败返回 null 而非抛错，调用方各自决定兜底。这挡掉了 LLM 应用里最常见的一类崩溃。

缺口

专注进行中关窗或刷新，没有任何拦截。全仓库 beforeunload 零命中。一次误关标签页丢掉的是正在计时的会话——在一个核心价值就是「专注被记录下来」的应用里，这是代价最高的可预防错误。

观察

表单校验以宽松为主。甘特/任务的日期与时长字段依赖 input 原生类型约束，没有跨字段校验（如结束早于开始）。对当前数据模型不致命，但会静默产生不合理记录，之后在统计页才暴露。

建议计时中注册 beforeunload；Electron 侧同理拦一次关闭。这是本次审计中投入产出比最高的一项。
06

识别优于回忆

Recognition rather than recall · 4.5 / 5

做到

一个搜索框同时搜页面和内容。GlobalSearch 把页面 / 任务 / 随记 / 场景四类结果同框呈现，命中字符 <mark> 加粗。组件注释点出了关键判断：「用户不必先想清楚要找的是页面还是某条任务。」——正是这条原则的定义。

做到

记录存路径而非译文。分心明细存的是 /focus 这样的路径，显示时经 PAGE_LABEL_KEYS 还原成当前语言的页面名。切换语言后历史记录不会僵在另一种语言上——一个容易被忽略、这里却处理对了的细节。

做到

该出现的地方有旁注。67 个组件用了 aria-label，共 351 处 aria 属性；图标按钮普遍配 title；42 条空态词条中相当一部分带 emptyHint 直接教下一步（ddl.page.emptyLine1/2 明说「在任务库中为任务设置截止日期后，这里会自动显示」）。

缺口

搜索结果不能用键盘走。GlobalSearch.jsx 没有上下键选中与回车跳转，也没有 aria-activedescendant；必须离开键盘去点。且它固定挂在侧栏顶部，侧栏折叠时得先触发 peek 才够得着。

07

使用的灵活性与效率

Flexibility and efficiency of use · 3.0 / 5

做到

界面本身可被用户裁剪。功能树让每个用户把用不到的页面整块关掉，废弃页面也能随时捡回。侧栏可折叠，折叠后左缘热区悬停即「窥视」滑出——常用与偶用两种节奏都照顾到了。

做到

局部有加速器。Esc 关闭在弹层里基本统一（ConfirmDialog 还用了捕获阶段监听）；ScenarioConfigAssistant.jsx:78 支持 Ctrl/⌘+Enter 直接触发；PresetRow 提供预设复用。

缺口

没有全局快捷键，也没有命令面板。全仓库 metaKey|ctrlKey 只有两处命中，其一还是排除条件。搜索框没有 Ctrl/⌘+K，「开始专注」「新建任务」这类高频动作必须每次走鼠标导航。在一个有 23 个页面的应用里，熟练用户没有任何提速路径。

缺口

已有的快捷键无处可查。Esc 关闭、Ctrl+Enter 触发这些都靠用户碰巧撞上。Tutorial 与设置页都没有快捷键一览。

观察

主题被金币解锁挡着。settings.theme.unlockHint 显示价格。对只是想要暗色以便夜里用的用户，把外观选项做成消耗品是一道摩擦——游戏化和可用性在这里正面冲突，值得单独定夺是否让暗色主题免费。

建议给 GlobalSearch 加 Ctrl/⌘+K 聚焦与上下键选中，顺手把它升格成命令面板（页面、任务、以及「开始专注」等几个动作项）。既补原则 7，也补原则 6 的键盘缺口。
08

美观与极简设计

Aesthetic and minimalist design · 3.5 / 5

做到

关键页面克制。主页只有三块：今日待办、临近截止、专注热力图。隐私首启卡只有三条 + 一个按钮，写法统一为「粗体一句说完 + 小字补一句」，注释还特意规定「别把结论藏进小字里」。回顾三页互不塞摘要。

做到

视觉系统是收敛的。单一 accent 派生全部衍生色，40 处 prefers-reduced-motion 适配，39 处 :focus-visible。

缺口

首次启动时侧栏是全开的 24 个入口、5 个分区。FeatureContext 的 disabled 默认空数组，即默认全开。对一个明确面向 ADHD 用户的产品，第一屏恰恰是认知负担最重的那一屏——而这时用户还没有任何依据判断哪些功能自己用得上。

功能树正是这个问题的解药，但它自己排在第四个分区「配置」里，用户往往在已经被淹没之后才发现它。

建议把首启默认改成精简集（专注 / 任务库 / 随记 / 截止日 / 时间轴 + 主页设置），并在隐私卡之后接一屏「想先开哪些？」的三选一（精简 / 全部 / 自定义 → 功能树）。默认全开与默认全关都不如让用户在第一分钟做一次选择。
09

帮助用户识别、诊断与恢复错误

Help users recognize, diagnose, and recover from errors · 3.5 / 5

做到

最危险的错误配了最直接的出口。存储写满时，警报条上直接放「导出」按钮——注释写明「用户不导出备份就点掉的话，丢的是真数据，所以只给一个明确的出口」。诊断与恢复合成了一次点击。

做到

导入结果双分支带具体信息。成功给出条数（importSuccess {count}），失败给出原因（importError {error}），而不是一句「操作失败」。

做到

页面级崩溃有兜底。ErrorBoundary 包住路由出口，渲染错误不会整站白屏，并提供刷新按钮，文案走 i18n。

缺口

网络与鉴权错误在界面上无法区分。aiClient.js:68 的 postProxy 只抛 HTTP ${status}。401（key 失效）、429（限流，等一会儿就好）、5xx（服务端问题）和断网在用户眼里长得一模一样，而这四种情况用户该采取的动作完全不同。

观察

ErrorBoundary 的文案过于笼统。只显示 common.error ＋刷新按钮，不说是哪一页出的问题，也不提「你的数据还在，刷新不会丢」——而后者恰恰是用户此刻最担心的事。

建议postProxy 按状态码分类抛出，UI 侧映射成三条可执行文案：「AI 密钥无效，去设置检查」「请求太频繁，稍后再试」「连不上服务器，检查网络」。
10

帮助与文档

Help and documentation · 3.0 / 5

做到

有一页说清了整套工作流。Tutorial 的六阶段把 23 个页面串成一条线，每阶段直接给入口链接，label 复用 nav.* 文案——不另造一套说法，因此永远不会和侧栏对不上。

做到

帮助是嵌在情境里的。设置每个分区有 settings-section-hint；空态不止说「没有」，还说「怎么才会有」。这类就地引导比集中式帮助页更容易被真正读到。

缺口

Tutorial 的体量撑不住 23 个页面。i18n/tutorial.js 只有 36 条词条，平均每阶段一句话。祈愿、生态缸、标本瓶架、技能树、场景这些自创系统，没有任何一处解释它们怎么运作、和别的系统什么关系。

缺口

新用户走不到 Tutorial。首启只有隐私卡，看完直接落在主页；主页三块里没有教程入口；Tutorial 埋在侧栏第四个分区。也没有任何页面级的 ? 帮助控件——本次审计未发现统一的 tooltip / 帮助体系。

建议隐私卡的按钮之后直接接 Tutorial（一次性），并在主页放一个可永久关闭的「看看怎么用」入口。文档写得再好，走不到就等于没有。
