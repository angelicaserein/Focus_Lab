三窗架构与单向数据流 electron/main.cjs 08-04 出生

桌面版同时开着三个 BrowserWindow，共用一份 preload，靠主进程注入的 --focuslab-role= 参数区分身份。

窗口形态职责
main1280×840 常规窗口，最小 900×600完整的 Focus Lab，localStorage 与全部业务状态的唯一 owner
pet320×460 无边框 / 透明 / 置顶 / 不进任务栏只画那只烧瓶 + 一个迷你面板，自己不存任何数据
flood屏幕下半张、鼠标穿透、置顶一块 canvas，把 0~1 的水位画成一摊会晃的水
  • 桌宠为什么是无状态的：两个渲染进程各写各的 localStorage 会打架（useLocalStorage 不监听跨窗口 storage 事件）。所以状态一律由主窗口经 IPC 单向推过去，桌宠上的操作也原样转回主窗口执行。代价是主窗口不能真被销毁 —— 点 X 只是 hide()，退出走托盘菜单。
  • 主窗口藏起来后 Chromium 会做 background throttling，里面的 setInterval 被掐到一分钟才跑一次，桌宠上的秒数就会卡住。主进程为此单独做了一层时间补偿：拿最后一次快照的时间戳自己往前推。
  • 桌宠窗尺寸固定不变，展开面板只是把内容画出来。曾经是 176 / 460 两档、点一下改窗口大小 —— 但透明无边框窗在 Windows 上每次 setBounds 都会先刷一帧再合成，看起来就是「闪一下才出现」。空白的上半截反正穿透，不占地方。
  • 桌宠位置记的是窗口右下角（也就是烧瓶所在处）的屏幕坐标，写进 userData/pet-window.json；面板往左上方长出去，烧瓶保持不动。拔掉外接屏后会被 clamp 回某块真实显示器内。
  • 置顶层级用的是 "screen-saver"（比普通置顶更高）+ setVisibleOnAllWorkspaces，全屏播视频 / 演示时桌宠也还在。

桌宠：桌面上那只烧瓶 src/pet/PetApp.jsx · usePetWindow.js 08-04 出生

就是沉浸式专注页里的同一只烧瓶（复用 FlaskGraphic），形状跟着烧瓶架 / 设置页的参数走。它没有情绪、不会饿也不会枯萎 —— 只有一个状态量：装到哪儿了。

  • 按轮廓穿透：窗口是矩形，画面里只有烧瓶那一小块是实体。光标不在实体上时整个窗口对鼠标透明，否则这块看不见的矩形会挡住底下的桌面图标。判定交给 CSS（只有 [data-pet-hit] 会被 elementFromPoint 命中），主进程用 setIgnoreMouseEvents(ignore, {forward:true}) —— forward 保证穿透状态下仍收得到 mousemove，不然一旦穿透就再也回不来了。
  • 迷你面板：当前计时 + 候选任务（最多 8 条）+ 开始专注暂停继续结束记一条…打开主窗口藏起来。文案没有拉整份 i18n 字典进这个 bundle，只内联了中英两组十来个词。
  • 草稿存在 PetApp 这一层而不是面板组件里：面板收起时会整个卸载，「打一半的记录 → 顺手切去别的程序」不该白打。
  • 拖动 / 点击 / 穿透三件事互相纠缠（拖动期间不能判定点击、也不能开穿透），单独抽成 usePetWindow；位移小于 4px 才算点击。
  • 桌宠点「开始专注」时，一次专注的状态活在 /focus 页的组件里 —— 而那是个懒加载路由，多半还没挂载。主进程为此把计时类指令额外暂存一份（带 id、10 秒 TTL），页面挂载后自己来认领；渲染层按 id 去重，「实时收到 + 挂载后认领」不会执行两次。

托盘：视野边缘那一格 electron/trayIcon.cjs · trayTooltip.cjs 08-04 / 08-17

  • 图标跟着水位变（08-17）：纯函数手绘一张 32×32 的 BGRA 位图喂给 nativeImage.createFromBitmap —— 圆形轮廓 + 从底部涨上来的水面，2×2 超采样抗锯齿。16px 上画不下瓶颈瓶身，圆是唯一还能看清「水到哪儿了」的形状。跑着是蓝、暂停压成灰蓝，一眼分得出，不用读 tooltip。
  • Tooltip：Focus Lab — 专注中 12:34，正计时显示已过、倒计时显示剩余、超时显示 +超出多久，跟桌宠面板上的时钟同一口径。没会话时只显示应用名，不显示 00:00。
  • tooltip 单独抽成纯函数只为一件事：能测。Electron 的 Tray 没有 getToolTip，装进 app 之后这句话在自动化里一个字都读不出来，只能靠人把鼠标停上去看。纯函数化之后中英、暂停、超时、超过一小时几个边界都进了 vitest。
  • 菜单：打开 Focus Lab / 开始专注 / 显示桌宠（checkbox）/ 开机自启（写注册表，带 --hidden）/ 检查更新 / 退出。
  • Windows 上通知和托盘按 AppUserModelID 归属，启动时 setAppUserModelId("com.focuslab.desktop") 与打包 appId 对齐 —— 不设的话系统通知里的发送者会显示成 electron.app.Electron，且点不回来。

全局快捷键 main.cjs · globalShortcut 08-04

  • Ctrl/Cmd+Shift+Space —— 无论人在哪个程序里，一键把桌宠叫出来并直接把光标送进「记一条」。想法冒出来的那一刻不用先找到应用。
  • Ctrl/Cmd+Shift+F —— 开始 / 暂停，不翻出任何窗口。一个键管两件事：有正在跑的会话就暂停/继续，没有就开一次新的。这是「专注」这件事本身最该有的那个键：想开始的那一刻，手不用离开当前的活。
  • 注册失败（被别的软件占了）不致命，静默跳过。

前台应用探测 electron/appWatch.cjs 08-04

「现在最前面的窗口属于哪个程序」—— 浏览器沙箱里永远拿不到的一件事，也是桌面版存在的最硬理由。

  • 没有用 active-win / get-windows 那类原生模块：它们要为每个 Electron ABI 重新编译，打包链路上会多一个在墙内下载失败的环节。改成起一个常驻的 PowerShell 子进程，里面 P/Invoke user32 的 GetForegroundWindow，每 1.2 秒往 stdout 打一行 JSON。零依赖、不用 rebuild，代价是 Windows-only。
  • 按需启动：只有功能开着、且正在专注时才拉起子进程。不专注的时候机器上不该有一个常驻进程盯着用户开了什么 —— 这既是省电，也是这功能唯一说得过去的隐私姿态。
  • 判定分三档：白名单外 = 分心；Focus Lab 自己永远不算；锁屏 / 开始菜单 / 输入法候选框这类系统外壳（lockapp searchhost textinputhost …）一律「维持原判」，一闪而过就翻瓶子会非常吵。
  • 白名单还空着时只采集不判定 —— 设置页那张勾选表就是探测器自己攒出来的，空名单时若不采集，名单就永远攒不出来，功能从第一次起就是死的。
  • 标题关键词这一道：浏览器整个勾进来是没办法的事，查论文和刷视频是同一个 msedge.exe，只有窗口标题分得开。但标题只在内存里比一次，比完就丢 —— 不落盘、不进记录、也不发给渲染层，分心明细里留下的仍然只有「Microsoft Edge」。
  • 切走的一段会按程序分段结账（10:03–10:07 Chrome、10:07–10:12 微信），短于 5 秒的「路过」不写进记录 —— 计时器照旧暂停，只是不留一条几秒钟的账。
  • 探测器在这台机器上跑不起来时会通知渲染层，设置页据此自己把开关关掉并说明原因（08-11），而不是留一个永远不生效的勾。

屏幕底部的积水 flood.html · src/flood/main.js 08-04

专注中切到白名单外的程序，桌宠的烧瓶就翻过来倒水，倒出去的水积在屏幕底部。涨满一屏要 4 分钟，回到白名单 45 秒退干净。

  • 一扇鼠标穿透、置顶、占屏幕下半张的透明窗，没有用 React —— 里面没有状态、没有交互、没有 DOM 结构，就一块 canvas。为它拉一份 React 只是让常驻窗口白白多占几十 KB。
  • 三条刻意的约束（用户拍板）：① 不扣真实专注进度，水位只是一面镜子，跑过的秒数一秒都不少；② 回到白名单立刻退潮，退得比涨快得多 —— 回头的动作要马上被奖励；③ 不设宽限期，切走就开始倒。之所以敢这么严，正是因为代价可逆又不真扣分。
  • 水一旦开始积就至少 56px 深：刚分心的头半分钟水位只有百分之几，在 1080p 上是最底下一条看不见的线 —— 而「有水了」本身才是那条信息，深浅只是量级。缓动会把这一跳抹成半秒的涌入。
  • 高 DPI 屏上 DPR 封顶 1.5、帧率封顶 30：水是一团模糊的色块，看不出锯齿，但这块半屏大的 canvas 按物理像素画填充量会翻几倍。
  • 分辨率变了 / 拔了外接屏就销毁重建（监听 display-metrics-changed 等三个事件），下次要用时按新尺寸摆。

睡眠、崩溃、单实例 main.cjs 08-11

  • 合盖睡眠：秒数是拿时间戳差值算的，睡一夜第二天打开会把整夜算进这次专注。于是借「切走」那条现成通路把计时按下暂停，但不发 segment —— 睡觉不是分心，明细里不该留账。消息带上判定时刻 ts，因为机器多半在渲染层处理完之前就已经睡死了，醒来后要把暂停补记在「睡着的那一刻」。
  • 锁屏（lock-screen）没有一并接进来：那是「人还在不在」的判断，跟这里「机器停了多久」不是一回事，要不要算暂停得先有个产品口径。
  • 渲染进程崩溃自愈：主窗口的渲染进程挂了（OOM、GPU 崩、three.js 把页面拖死）不能就这么算了 —— 它是全部状态的唯一 owner，没有它桌宠就没有数据来源，而用户看到的只是「桌宠不动了」，没有任何报错。所以就地重建；这次专注的计时跟着页面一起没了，与其让桌宠停在一个永不前进的进度上，不如干净地退回待机态。崩之前是藏着的（托盘常驻用法），重建后也不会突然弹到用户脸上。
  • 单实例锁：第二次启动只是把已有窗口唤到前面。开机静默启动：注册表里那条命令带 --hidden，主窗口照样创建（它是数据源），只是不弹出来，开机后看到的只有托盘和桌宠。
  • 退出时 globalShortcut.unregisterAll() + 停掉探测子进程 —— 那是我们 spawn 出来的，不收拾会留在任务管理器里。
  • 外链走系统浏览器（setWindowOpenHandler 一律 deny + shell.openExternal），不在 app 里开一个没有导航栏的窗口。

拖文件建任务 src/hooks/desktop/useDesktopFileDrop.js 08-17

把文件拖进主窗口 → 建成一条任务，任务记着这个文件在硬盘上的位置，点一下用系统默认程序打开。

  • 桌面版真正独一份的一件事：浏览器的 drop 只给你文件内容，拿不到路径，更不可能回头把它打开。网页版最多做到「把文件读进来」，这里做到的是「这条任务对应硬盘上那个文件」。Electron 32 起 File.path 被移除，走的是 preload 里的 webUtils.getPathForFile。
  • 为什么值得做：从想到「该改论文了」到真的开始改，中间隔着「找到那个文件」。那一步看着不算什么，却正是最容易在半路走神的地方 —— 拖一下就把这段路省了。
  • 靶子是主窗口而不是桌宠：桌宠为了不挡桌面图标是鼠标穿透的，而穿透的窗口在 Windows 上根本不会被注册成拖放目标，收不到 drop。
  • 文件名 → 标题：去扩展名、下划线/连字符还原成空格（实验设计_v3.docx → 实验设计 v3）。标题是给人读的，扩展名已经由旁边的「打开」按钮代表了。
  • 只认「从系统里拖文件进来」（dataTransfer.types 含 Files），页面内部拖任务卡排序的那些不接管；dragenter/dragleave 进出各记一笔，不然子元素之间冒泡会闪。

自动更新与打包 electron/updater.cjs · electron-builder.yml 08-17

网页版改一版、刷新就是新的；装在硬盘上的 exe 不会自己变。

  • 三条克制的规矩：① 绝不主动重启 —— 下载完只是备好，安装发生在用户自己退出之后。中途弹一个「立即重启」会直接打断正在计时的会话，那是这个 app 最不该做的事。② 后台检查失败一律静默 —— 墙内从 GitHub 拉东西失败是常态，弹红框既没可操作性也只是打扰；只有用户从托盘主动点「检查更新」时才每种结果都回话。③ 只在打包后的正式版里跑。
  • 启动后延迟 10 秒才查：开机自启时别一上来就抢网。
  • 打包 files: 只带 dist/ + electron/ + package.json，前端依赖已经在 vite build 时打进 dist 了。唯一例外是 electron-updater 及其整条依赖链 —— 它是主进程运行时 require 的，必须真的进包。
  • 产物：Windows NSIS（可改安装目录、建桌面和开始菜单快捷方式）、macOS dmg（x64 + arm64）、Linux AppImage。发版时 latest.yml 必须跟安装包一起传到 Release，少传这个文件客户端永远发现不了新版本。
  • 安装包没有代码签名，Windows 上更新后首次启动可能仍会过一次 SmartScreen —— 那是证书的事。

手机端（PWA）

没有独占功能 manifest.webmanifest · sw.js · 78 处媒体查询
先把话说清楚 手机端没有任何一件桌面 / 网页上没有的功能。它走的是另一条路：同一套功能，让它在小屏上不难用、能装进主屏、断网也打得开。所以下面列的全是「壳 + 优化」，一条新功能都没有 —— 这不是遗漏，是当时的取舍：手机上真正缺的能力（后台计时、锁屏通知、前台应用探测）浏览器都给不了，硬做只会做出一个残废版本。

PWA 三件套 public/manifest.webmanifest · public/sw.js · src/utils/registerSW.js 06-29 出生

  • manifest：display: standalone（进主屏后没有地址栏）、orientation: portrait-primary、主题色 #ac6c9f、192/512 两档图标且 purpose: "any maskable"（安卓自适应图标不会被裁掉边）。start_url 和 scope 都是相对路径 ./，配合 Vite 的 base: './'。
  • iOS 那一套额外的：apple-touch-icon、apple-mobile-web-app-capable、状态栏样式、主屏标题 —— Safari 至今不完全吃 manifest。
  • SW 缓存策略四条分流：导航请求走网络优先、断网回退到缓存的 index.html（HashRouter 下所有路由都是同一个文件，所以离线也能进任意页）；同源静态资源缓存优先；/api/*（AI 对话）永不缓存；跨域直接放行不拦截。
  • 构建清单驱动的清理：Vite 产物文件名带 hash，每发一版就是一批新文件名。没有清单就只能靠手动 bump 版本号才淘汰，否则旧 bundle 和 .glb 模型会永远躺在同一个 cache 里，发几版就是几十 MB。现在由 vite.config.js 的 sw-build-manifest 插件把占位符替换成真正的文件数组，activate 时把不在本次构建里的条目删掉 —— 而未变动的 hash 资源仍然命中缓存、不必重下。
  • dev 下主动注销 SW 并清空 Cache Storage：跑过一次 build/preview 之后 SW 会常驻浏览器并对 JS 走缓存优先，导致 dev 时拿到旧的坏 bundle（表现为 Cannot read properties of null (reading 'useState') 这种莫名其妙的报错）。

原生手感 index.html · src/styles/global.css 07-19

一次提交、六行 CSS，把「一个网页」和「一个 app」之间那点违和感抹掉。

怎么跑 / 怎么打包

命令做什么
npm run dev网页版开发（5173，strictPort）。SW 不注册，还会主动清掉残留的
npm run desktop:dev拉起 vite 后等它真的听上端口再起 Electron。没引 concurrently / wait-on —— 为这一件事加两个包不值当
npm run desktop:packvite build + electron-builder --dir，出免安装目录，验证打包后行为
npm run desktop:build出正式安装包到 release/
npm run build && npm run preview唯一能验证 PWA（SW + 可安装）的路径 —— dev 下这套是关着的
  • dev-desktop.mjs 里有一行 delete childEnv.ELECTRON_RUN_AS_NODE：从 Electron 系的终端（部分 IDE 内置终端、Claude Code）启动时环境里会带着它，会让 electron 二进制退化成纯 node 跑，require("electron") 只返回一个路径字符串，主进程一上来就 TypeError。
