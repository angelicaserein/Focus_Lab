# 桌面版与桌宠

Focus Lab 可以用 Electron 打包成桌面 app。桌面版比网页版多一样东西：
一个常驻桌面的**桌宠悬浮窗**——就是沉浸式专注页里的那只烧瓶，直接飘在桌面上。

## 跑起来

```bash
npm run desktop:dev     # 开发：起 vite + Electron（改代码热更新）
npm run desktop:pack    # 只打包成免安装目录 release/win-unpacked/
npm run desktop:build   # 打成安装包 release/*.exe
```

网页版完全不受影响：`npm run dev` / `npm run build` 一切照旧。

## 三个窗口

| 窗口 | 内容 | 数据 |
|------|------|------|
| 主窗口 | 完整的 Focus Lab（侧边栏 + 全部页面） | 持有全部 localStorage |
| 桌宠窗 | 一只烧瓶 + 展开后的迷你面板 | **不存任何数据**，全靠 IPC |
| 积水窗 | 贴在屏幕底部的一块 canvas | 只收一个 0~1 的水位数 |

桌宠刻意做成无状态的：localStorage 只能有一个 owner，两个渲染进程各写各的会打架
（`useLocalStorage` 不监听跨窗口 storage 事件）。所以数据单向流动——

```
主窗口 ──publishState(补丁)──▶ 主进程(合并) ──desktop:state──▶ 桌宠
主窗口 ◀────desktop:command──── 主进程 ◀──sendCommand──── 桌宠
```

代价是主窗口不能真的被销毁：点 X 只是隐藏，退出走托盘菜单。

状态快照分两段，由主进程浅合并：

- `app` 段 —— 由 [`DesktopHost`](../src/components/desktop/DesktopHost.jsx) 常驻发布：
  任务、语言、主题、烧瓶形状参数。桌宠不持有任何偏好，主题只能这么跟：
  收到 `app.theme` 就写自己的 `<html data-theme>`，配色由 `theme.css` 那套变量接管
  （桌宠窗只引变量表，不引主 app 的元素样式）。
- `focus` 段 —— 由 [`useDesktopFocusSync`](../src/hooks/desktop/useDesktopFocusSync.js) 发布，
  **只在 `/focus` 页面挂载时存在**。离开专注页会发 `{ focus: null }`，桌宠退回空瓶。

一次专注的计时状态活在 `FocusPage` 组件里（`useFocusTimer`），页面卸载会话就没了。
所以桌宠的「开始专注」在主进程侧会先把主窗口切到 `#/focus`，等 hook 挂载上来才有人接得住。

## 桌宠的行为

- **拖动 + 记忆位置**：按住烧瓶拖到桌面任意角落，位置存在
  `%APPDATA%/Focus Lab/pet-window.json`（存的是窗口右下角坐标，展开面板时这个角不动）。
  没用 CSS 的 `-webkit-app-region: drag`——那样系统会吞掉鼠标事件，同一块区域就没法既能拖又能点。
- **点击展开**：按下到抬起位移小于 4px 判定为点击，展开迷你面板（当前任务 / 开始暂停结束 / 记一条）。
- **鼠标穿透**：光标不在烧瓶或面板上时整个窗口对鼠标透明，不会挡住底下的桌面图标。
  靠 `setIgnoreMouseEvents(ignore, { forward: true })` + 渲染层 `elementFromPoint` 判定，
  实体区域在 DOM 里用 `data-pet-hit` 标记。
  判定精确到**瓶子的轮廓**而不是它的外接方块：窗口里除了 `.flask-hit`（烧瓶轮廓的一份
  不上色副本，描边加宽留出指针余量）之外的一切都设了 `pointer-events: none`，
  所以环外和四角照旧穿透。也正因如此，窗口尺寸可以比瓶子宽松，不必贴着瓶身裁。
- **专注计时同步**：烧瓶液面 = 已过时长 / 目标时长（和沉浸层同一口径），外圈还有一道进度环，
  计时进行中环会缓慢呼吸，暂停即静止。
- **托盘 + 全局快捷键**：托盘右键可开关桌宠 / 开机自启 / 退出；
  `Ctrl+Shift+Space` 随时唤起桌宠并把光标放进「记一条」输入框（写进备忘录）。

烧瓶没有情绪，也不会饿、不会枯萎。它只有一个状态量：装到哪儿了。
不专注的时候它就是空的，不表达任何评价。

## 分心水位

默认关闭，在「设置 → 计时 → 分心水位」里开。开了之后：

专注进行中，如果最前面的程序不在你勾的白名单里，桌宠的烧瓶就翻过来往外倒水，
倒出去的水积在屏幕底部那块透明窗上。回到白名单立刻退潮，水一滴不少地回到瓶里。

三条刻意的设计约束，它们是互相支撑的一整套：

1. **不扣已经跑过的进度**。水位只是一面镜子，倒出去多少水都不会让 `seconds` 变小
   （切走期间计时器是暂停的，见下一节：不再往前走，但也不回退）。
2. **回到白名单立刻退潮**，而且退得比涨得快得多（涨满 4 分钟，退空 45 秒）。
   回头的动作要马上被奖励。
3. **不设宽限期**，切走就开始倒。之所以敢这么严，正是因为 1 和 2：
   代价可逆、又不真的扣分，严格才不至于变成惩罚。

### 翻瓶子 = 分心

瓶子翻过来那一下和用户自己按「我分心了」是同一件事，所以它同时触发另外两件：

- **计时器暂停**。人在别的软件里的那段时间不该算进专注。只恢复我们自己按下的
  那一次——切走期间用户手动按过的暂停不会被顶掉。
- **自动记一条分心**（`type: "app"`）。回到白名单时结账，记的是「几点到几点、
  用的哪个程序」，直接出现在 /distraction 的会话明细里；程序名同时当标签用，
  于是「分心原因排行」排出来的就是把人拽走的那几个软件。
  切走期间换了程序就分段结账（`10:03–10:07 Chrome`、`10:07–10:12 微信`），
  短于 5 秒的路过只暂停、不记账，免得明细页被几秒钟的噪音刷满。

不弹打标签的弹窗：用户此刻人在别的软件里，弹窗只会在他回来时糊一脸，
而「用的哪个程序」本身已经比手打的标签更准了。

实现上是主进程发三类事件（`desktop:distraction` 的 `enter` / `leave` / `segment`），
渲染层 `useDistractionTracking` 接住。注意闸门（`watchGateOpen`）不能只看
`isRunning`：自动暂停会把它变成 false，闸门一关就再也收不到「回来」的那一下，
计时器会永远醒不过来——所以「因切走而暂停」的会话也算闸门开着。

### 怎么知道你开着什么

`electron/appWatch.cjs` 起一个常驻 PowerShell 子进程，里面 P/Invoke user32 的
`GetForegroundWindow`，每 1.2s 往 stdout 打一行 JSON（进程名 / 友好名 / 窗口标题）。

没用 `active-win` / `get-windows` 那类原生模块：它们要为每个 Electron ABI 重新编译，
打包链路上多一个会在墙内下载失败的环节。代价是这个功能 **Windows-only**，
其他平台上 `SUPPORTED` 为 false，整块功能连设置项都不生效。

> 写 `.ps1` 时必须带 UTF-8 BOM。Windows PowerShell 5.1 没有 BOM 就按系统 ANSI
> 解码，脚本里的中文注释会变成乱码，乱码里随机出现的引号直接把语法解析坏，
> 报的还是「第 47 行意外的 `}`」这种完全指不到病根的错。

白名单里存的是进程名（`code`、`winword`），但**不让用户自己填**——
「Word 的进程名叫 WINWORD」这种知识不该由用户来提供。列表是探测器自己攒的：
专注时用过什么，它就出现在设置页里，勾一下即可。首次使用时表是空的，
得先跑一次专注让它见见世面。

### 隐私姿态

这是整个 app 里唯一一个会看向应用之外的功能，所以：

- 默认关，必须显式 opt-in（和桌面通知同一个道理）。
- **探测子进程按需启动**：只有「开着 + 有一次没结束的专注会话」同时成立时才拉起来，
  会话一结束立刻 kill。不专注的时候机器上不该有一个常驻进程盯着用户开了什么。
  （白名单空着时照样采集但一律不判分心——那张表就是探测器攒出来的，
  不采集就永远攒不出来；而「因切走被自动暂停」的会话仍算没结束，见上一节。）
- 窗口标题只用来判定「这是不是桌面/任务栏」，不落盘、不进任何统计、不发给任何地方。
  设置页那张表里只有程序名。

### 积水窗的几个取舍

- 只占**工作区**下半（`FLOOD_MAX_RATIO`），不是全屏。一个全屏透明窗常驻画波浪，
  风扇会转起来。
- 用 `workArea` 而不是 `bounds`：`bounds` 含任务栏那一条，水会从屏幕最底下开始积，
  头几十像素全被任务栏挡着——任务栏是系统级 topmost，抢不过它。
- 水一开始积就至少 `MIN_DEPTH_PX` 深。没有下限的话，刚分心的头半分钟水位只有百分之
  几，在 1080p 上是最底下二三十像素的一条，跟没有一样。**「有水了」本身才是那条信息，
  深浅只是量级**；一条看不见的水等于这功能在最该说话的时刻是哑的。
- 水位归零就 `hide()` 整个窗口，桌面上不留空转的透明窗。
- 全程 `setIgnoreMouseEvents(true)`（不带 forward——它压根不需要知道鼠标在哪），
  `focusable: false`，显示用 `showInactive()`：它盖在别人正在用的窗口上面，
  抢一次焦点就会把用户从正在打字的地方踢出去。
- 置顶层级是 `pop-up-menu`，低于桌宠的 `screen-saver`——水要在瓶子后面。
- `backgroundThrottling: false`：这个窗口的全部意义就是「用户在别的程序里的时候
  还在动」，默认的后台节流会把水面掐到几乎不动。
- 只画在主显示器上。分辨率变了 / 拔了外接屏会销毁重建（`display-metrics-changed`）。

### 瓶子怎么倒

`FlaskGraphic` 多了个 `drainToNeck`：水往瓶口那头退，而不是往瓶底退。
桌宠把瓶身整个转了 180°，屏幕上的「下」就是瓶子的「上」，不翻这个方向的话
水会顺着瓶底往上升出去，跟倒水正好相反。

两边同时翻（瓶子转、液柱反向）在屏幕坐标里恰好互相抵消：看起来就是玻璃绕着
一摊不动的水转过去，然后水才从瓶口漏下来。翻转只作用在瓶身上，进度环留在原地。

## AI 功能

桌面版页面跑在自定义的 `app://` 协议下，没有同源的服务端，`/api/*` 代理会 404。
打包前需要把代理指向已部署的站点：

```bash
# .env.production.local
VITE_API_BASE=https://<你的 vercel 域名>
```

不设的话 AI 相关功能会失败并各自走兜底（示例内容 / 报错提示），其余功能不受影响。

## 已知的环境问题

Windows 上首次 `npm run desktop:build` 可能报：

```
ERROR: Cannot create symbolic link : 客户端没有所需的特权
```

这是 electron-builder 解压签名工具包时需要创建符号链接。二选一：

- 打开「设置 → 系统 → 开发者选项 → 开发人员模式」（一次性，推荐）；
- 或用管理员权限的终端跑打包命令。

急着出个能跑的产物、不在意 exe 图标和版本信息的话，可以临时加
`-c.win.signAndEditExecutable=false` 绕过。
