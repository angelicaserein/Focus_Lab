# Git → Notion 工作日志脚本 · 使用说明

> 这个文件是给你自己看的。脚本本体在同一个文件夹里:`scripts/git-notion-logger/`。

## 这是干嘛的

它在后台盯着你的项目文件。你**保存文件**时,它会:

1. 用 git 对比出"上次记录到现在"改了什么;
2. 把改动发给 Claude(`claude-sonnet-4-6`),让它总结成**功能层面**的描述(不写文件名、不写代码细节);
3. 把结果写进你的 Notion 数据库,一个主题一行。

每行包含三列:

- **Name**:英文主题短语,如 `Improve todo list UX`
- **中文**:一句话概括
- **description**:中文功能点编号列表,如 `1.增加编辑和可撤销删除 2.优化动画过渡`

如果一次改动里有好几个**独立功能**,它会自动写**多行**;同一个功能下的小点合并到一行的 description 里。

---

## 怎么用(最常用的三件事)

先在 VS Code 里按 `` Ctrl+` `` 打开终端,再用下面的命令。

### ▶️ 启动

```powershell
npm run journal
```

看到 `git-notion-logger started.` 就是起来了。之后你改文件 + 保存(Ctrl+S),过 2 秒它就会写 Notion。

> 这样启动是"前台运行",那个终端会一直显示日志。**别关那个终端**,关了脚本就停了。

### ⏹️ 关闭

- 如果是你在终端里启动的:在那个终端按 **`Ctrl+C`**。
- 如果找不到那个终端(比如是后台起的):新开一个终端跑这条,杀掉脚本进程:

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -like '*git-notion-logger*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

### 🔍 查它现在有没有在跑

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -like '*git-notion-logger*' } | Select-Object ProcessId, CommandLine
```

有输出 = 在跑;没输出 = 没跑。

## 触发时机和"会不会很碎"

当前设置:**保存一次 = 写一行**(`.env` 里 `TRIGGER_MODE=watch`、`WATCH_DEBOUNCE_MS=2000`)。

- 那 2 秒只是技术去重:你按一次 Ctrl+S,系统底层会触发好几个文件事件,2 秒窗口把它们合并成"一次保存"。对你来说就是即时的。
- 两次保存间隔超过 2 秒 = 各自成行。

**如果觉得行太碎、想"一段工作汇总成一行"**:把 `.env` 里的 `WATCH_DEBOUNCE_MS` 调大,比如:

- `120000` = 停手 2 分钟后才汇总一次
- `300000` = 停手 5 分钟后才汇总一次

改完 `.env` 要**重启脚本**(关掉再 `npm run journal`)才生效。

---

## 花不花钱 / 费不费 token

- **没改动 = 不调用 Claude = 不花钱。** 保存了但内容没变,或只动了被排除的目录,都会直接跳过。
- 只有真有改动时才发给 Claude。单次大概几分钱;改得多、diff 大时会多一点(diff 超过 6 万字符的部分会被截断,防止暴涨)。
- 不想让它跑的时候,直接按上面的方法**关掉**,就彻底不工作、不花钱。

## 可以改的配置(都在 `.env` 里)

文件:`scripts/git-notion-logger/.env`(这个文件不会被提交到 git,放心填密钥)

| 配置项                   | 作用                                 | 默认                |
| ------------------------ | ------------------------------------ | ------------------- |
| `ANTHROPIC_API_KEY`      | Claude 的 key                        | (必填)              |
| `NOTION_TOKEN`           | Notion 集成 token                    | (必填)              |
| `NOTION_DATABASE_ID`     | 写入哪个数据库                       | (必填)              |
| `TRIGGER_MODE`           | `watch`=保存就写 / `interval`=定时查 | `watch`             |
| `WATCH_DEBOUNCE_MS`      | watch 模式的合并窗口(毫秒)           | `2000`              |
| `CHECK_INTERVAL_MINUTES` | interval 模式的间隔(分钟)            | `30`                |
| `CLAUDE_MODEL`           | 用哪个模型                           | `claude-sonnet-4-6` |
| `EXCLUDE_PATHS`          | 不参与统计的目录,逗号分隔            | `node_modules,dist` |
| `MAX_DIFF_CHARS`         | 发给 Claude 的 diff 字符上限         | `60000`             |

> 改完任何配置,都要**重启脚本**才生效。

## Notion 数据库要求

数据库里要有这三列,**名字和类型都要对上**:

| 列名          | 类型        |
| ------------- | ----------- |
| `Name`        | 标题(Title) |
| `中文`        | 文本(Text)  |
| `description` | 文本(Text)  |

并且要把数据库**共享给你的 Notion 集成**:数据库右上角 `•••` → Connections → 选你的集成。否则写入会报 403。

(如果你的列名不一样,可以在 `.env` 里用 `NOTION_PROP_NAME` / `NOTION_PROP_CHINESE` / `NOTION_PROP_DESCRIPTION` 覆盖。)

## 常见问题

- **保存了但 Notion 没动静?**
  1. 先确认脚本在跑(上面的"查"命令);
  2. 看启动脚本的终端有没有报错(比如 Notion 403 = 没共享数据库或列名不对;401 = key 不对);
  3. 确认你改的不是被排除的目录(`node_modules` / `dist`)。
- **怎么知道它成功写了?** 启动脚本的终端里会打印 `→ 主题名` 和 `done ✓`。
- **它和我的提交冲突吗?** 不冲突。它用的是一个临时 git 索引来对比,**绝不碰你真正的暂存区和工作区**。
- **状态存哪?** 存在 `.git/focus-notion-state.json`,不会被提交。

## 小结:开始工作前

1. `npm run journal` 启动;
2. 正常写代码、正常 Ctrl+S;
3. 去 Notion 数据库看记录;
4. 不用了就 `Ctrl+C` 或杀进程关掉。
